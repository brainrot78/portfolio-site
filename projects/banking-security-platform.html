Next-Gen Banking
Security Platform

01 / The idea

Defence in depth,
end to end.

Banks are attacked at every layer: volumetric DDoS at the edge, injection at the web tier, brute force against remote access, malware on endpoints and privilege escalation inside Active Directory. I wanted a lab where each of those attacks is met by a dedicated control, and where every control reports to one place.

The result is seven layers of protection feeding a SOC stack that adds threat intelligence to each alert, opens a case, runs a playbook and writes the report. AI helps with detection and reporting. The response logic stays rule-based.

02 / Architecture

Seven layers, outside in

  1. L1

    Edge: DNS & DDoS protection

    Public DNS and DDoS mitigation through Cloudflare, which also keeps the origin IP hidden.

    Cloudflare

  2. L2

    Perimeter firewall & remote access

    pfSense at the perimeter with strict ingress rules. Admin access only through a hardened WireGuard VPN, with nothing exposed directly.

    pfSenseWireGuard

  3. L3

    DMZ: web tier & deception

    An Nginx reverse proxy behind BunkerWeb and the Naxsi WAF. Naxsi runs in learning mode to build its allow-list from real traffic, then switches to blocking. A T-Pot honeypot in the DMZ attracts attackers and gathers their indicators.

    NginxBunkerWebNaxsiT-Pot

  4. L4

    Network IDS / IPS

    Suricata and Snort inspect traffic between zones, raising alerts and blocking known-bad patterns.

    SuricataSnort

  5. L5

    Internal segmentation

    A second firewall, OPNsense, separates the DMZ, server, user and SOC zones, so a compromise in one zone can't spread freely.

    OPNsense

  6. L6

    Endpoints & servers

    Application servers, Active Directory, a NAS and user endpoints, each running a Wazuh agent for EDR. On top of that sit ML-based malware detection and UEBA to spot unusual user and host behaviour.

    Wazuh EDRML malware detectionUEBAActive DirectoryNAS

  7. L7

    SOC: intelligence & response

    Wazuh as the central SIEM. MISP and OpenCTI for threat intelligence, enriched from public sources such as AlienVault OTX and with AI-generated context. n8n for SOAR, with TheHive and DFIR-IRIS for cases and ticketing.

03 / Automated response

Playbooks for the alerts that matter most

Each playbook follows the same path: detect → enrich → score → open case → respond → report. The n8n workflow pulls context from MISP, OpenCTI and public reputation sources, then opens a case in TheHive or DFIR-IRIS so the analyst starts with everything already gathered.

Playbook

SSH brute force

Repeated failed logins trigger a Wazuh alert. The source IP is checked against threat intelligence and reputation feeds, then a case is opened with the verdict and the recommended containment.

Playbook

Malware detection

EDR and ML detections are matched against YARA rules, and file hashes are enriched with intelligence. The affected host and the related indicators go into the case and back into MISP.

Playbook

AD privilege escalation

Suspicious changes to privileged groups and unusual account behaviour flagged by UEBA are escalated with the user's and host's context for fast triage.

AI

AI audit reports

Wazuh findings are summarised by an LLM into readable audit reports, turning raw alerts and compliance results into something management can act on.

Red team

Automated pentests

Scheduled Nmap-based scans and attack runs against the infrastructure check that every layer actually detects and blocks what it should, and catch new exposures early.

Detection

Custom rules

15+ custom YARA and Wazuh rules written for the banking scenario. Together with the ML models, they detected 92% of the malicious logs in testing.

04 / Takeaways

What I learned

Integration is the hard part. Each tool works fine on its own. The real engineering is getting consistent fields, timestamps and identifiers across a firewall, a WAF, an EDR and a SOAR, so a single incident reads as one story.

Deception pays off. The honeypot produced fresh, local indicators that fed straight into MISP and made the other layers sharper.

Automate the boring 80%. Once enrichment and case creation were automatic, analyst time went to the decisions that actually needed a human.
